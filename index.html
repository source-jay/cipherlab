>_ KNOWLEDGE BASE / 04

CIPHER GUIDE

Understand the ideas behind the algorithms.

⫶
TRANSPOSITION

RAIL FENCE CIPHER

A transposition cipher that rearranges the positions of characters. The message is written diagonally across a set number of rails and then read row by row.

PLAINTEXT → ZIGZAG → ROW READ → CIPHERTEXT

Key

The number of rails controls the zigzag pattern. A minimum of two rails is required.

⇄
SUBSTITUTION

MONOALPHABETIC SUBSTITUTION

A substitution cipher replaces each plaintext letter with another letter according to a fixed alphabet mapping. The same mapping is used throughout the message.

PLAINTEXT → LETTER MAP → CIPHERTEXT

Key

A permutation of the 26 English letters. Every letter must appear exactly once.

⚿
PUBLIC-KEY ENCRYPTION

RSA (RIVEST–SHAMIR–ADLEMAN)

An asymmetric algorithm (1977) that uses a public key to encrypt and a matching private key to decrypt. Anyone can lock a message for you; only you can unlock it. Its security rests on the difficulty of factoring a very large number n back into its two secret primes.

KEYGEN: p, q → n = p·q → φ(n) → e → d = e⁻¹ mod φ(n)
ENCRYPT: c = mᵉ mod n  ·  DECRYPT: m = cᵈ mod n

Key

Public key (n, e) is shared freely. Private key (d, n) must stay secret. CipherLab uses 2048- or 3072-bit moduli with OAEP padding and SHA-256.

[ EXPAND FULL BRIEFING ]

How it works

Pick two large random primes p and q, multiply them to get the modulus n, and compute Euler's totient φ(n) = (p−1)(q−1). Choose e (usually 65537) coprime with φ(n) and compute d so that e·d ≡ 1 (mod φ(n)). Raising to e and then to d returns the original number, because m^(e·d) ≡ m (mod n).

Key concepts

  • Trapdoor one-way function — easy to compute, hard to invert without d.
  • Modular exponentiation and modular inverses.
  • Padding (OAEP) adds randomness so equal plaintexts give different ciphertexts.

Workflow

SENDER: plaintext → OAEP-pad → c = mᵉ mod n → ciphertext
RECEIVER: ciphertext → m = cᵈ mod n → OAEP-unpad → plaintext

Advantages

  • No shared secret has to be exchanged in advance.
  • The same key pair can also produce digital signatures (RSA-PSS).
  • Extremely well studied and supported everywhere.

Limitations

  • Slow and can only encrypt short messages (≈190 bytes for 2048-bit OAEP-SHA-256).
  • Large keys compared with elliptic-curve cryptography.
  • Textbook RSA without padding is insecure; broken by large quantum computers.

Real-world applications

TLS/HTTPS certificates, SSH keys, PGP email, code signing, and wrapping symmetric (AES) keys in hybrid encryption.

✎
DIGITAL SIGNATURE

DSA (DIGITAL SIGNATURE ALGORITHM)

A NIST standard (FIPS 186) for signing data, not encrypting it. A signature proves the message came from the holder of the private key and has not been altered. Security relies on the discrete logarithm problem in a prime-order subgroup.

SIGN: r = (gᵏ mod p) mod q  ·  s = k⁻¹(H(m) + x·r) mod q
VERIFY: v = (g^u₁ · y^u₂ mod p) mod q  →  valid ⇔ v = r

Key

Domain parameters (p, q, g) are public. Private key x is random in [1, q−1]; public key y = gˣ mod p.

[ EXPAND FULL BRIEFING ]

How it works

The signer hashes the message, picks a fresh secret nonce k, and computes the pair (r, s). The verifier uses only public values — p, q, g, y and the message hash — to recompute v. If v equals r, the signature is valid.

Key concepts

  • Discrete logarithm: given y = gˣ mod p, finding x is infeasible.
  • Hash function (SHA-256) — the signature covers the digest of the message.
  • Per-message nonce k must be secret, unpredictable and never reused.

Workflow

SIGNER: message → SHA-256 → (r, s) with private x
VERIFIER: message + (r, s) + public y → VALID / INVALID

Advantages

  • Provides authenticity, integrity and non-repudiation.
  • Small signatures relative to the key size.

Limitations

  • Cannot encrypt data — signatures only.
  • Reusing or leaking k reveals the private key x.
  • Legacy: FIPS 186-5 (2023) no longer approves DSA for new signatures; ECDSA/EdDSA are preferred.
  • Not supported by the browser Web Crypto API.

Real-world applications

Historically used in government systems, SSH (ssh-dss), PGP/GnuPG keys and software signing; today it is mostly encountered when verifying older signatures.

SECURITY NOTE

CLASSICAL CIPHERS ARE NOT SECURE BY MODERN STANDARDS

These algorithms are valuable for learning cryptographic concepts, but they should not be used to protect real-world sensitive information. Monoalphabetic substitution is vulnerable to frequency analysis, while Rail Fence preserves the original character frequencies.
